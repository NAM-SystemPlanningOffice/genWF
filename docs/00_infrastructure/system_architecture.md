# システム構成要素

## 1. システム概要

ワークフロー申請・承認システムは、システム関係の各種申請業務と承認フローを管理するWebアプリケーションです。

### 技術スタック

- **アプリケーション**: Python 3.13 + Flask
- **本番環境**: Azure App Service (Linux) + Gunicorn + Entra ID Easy Auth
- **開発環境**: Flask開発サーバー（ローカルPC）
- **データベース**: Oracle Database COMDB (開発/Staging: ホストcom-dbdv、Production: ホストcom-db、スキーマ: NAM_TASK)

詳細な技術仕様: [../reference/TECH_SPECS.md](../reference/TECH_SPECS.md)

### 設計思想
- 設定情報をOracleDBで管理することにより、柔軟に申請業務・承認フローを追加可能
- プルダウン選択肢やバリデーションロジックもDB管理
- 承認後の自動設定を重視したデータ設計

## 2. 主要構成要素

### A. 申請オンライン

申請者が各種申請を行うためのWebインターフェース。

#### 機能特性
- **動的フォーマット**: 申請種類により入力項目・画面フォーマットが動的に変化
- **複数レコード対応**: 申請内容が単一レコードまたは複数レコードの両方に対応
- **申請区分**: 単一レコード：新規作成/修正（削除も含む）、複数レコード：（レコード単位に）新規作成/修正/削除
- **既存設定参照**: 修正・削除時は既存リソース（設定）を検索・参照
- **重複チェック**: 新規作成・修正時に既存リソースとの重複を自動チェック
- **データ検証**: プルダウン選択とバリデーションによるデータ品質確保

#### 主要機能

1. **新規作成申請**
   - 申請種類を選択
   - 入力フォームにすべての項目を入力
   - 既存リソースとの重複チェック（例: Gmailグループのメールアドレス重複チェック）
   - 一時保存・申請提出

2. **修正申請**
   - 申請種類を選択
   - 既存リソースを検索・選択
   - 既存設定値が自動入力されたフォームで編集
   - 変更可能フィールドと変更不可フィールドを区別
   - 変更内容の差分確認
   - 一時保存・申請提出

3. **削除申請**
   - 申請種類を選択
   - 既存リソースを検索・選択
   - 削除対象の内容を確認（読み取り専用）
   - 削除理由を入力
   - 申請提出

4. **共通機能**
   - 申請内容の一時保存（下書き）
   - 下書きからの再開・編集
   - 申請提出前の確認


### B. ワークフローオンライン

申請内容を承認フローに沿って処理するための管理画面。

#### 承認フロー構造

```
[申請者] → [申請対象者の所属長] → [申請対象オブジェクトの所管の所属長]* → [その他承認者]* → [報告]*

* 申請種類により省略または追加される
```

#### 承認フローの特性

2. **申請者の所属承認**
   - 申請者の所属長承認

3. **所管承認**
   - 申請種類によっては申請対象オブジェクトの所管の所属長承認が必要
   - ただし、申請者の所属 = 申請対象オブジェクトの所管の場合は省略

4. **その他承認（申請種類による）**
   - 経営企画部長承認
   - 法務コンプライアンス部長承認
   - システム企画室承認
   - システム開発部長承認
   - その他の承認

5. **報告（申請種類による）**
   - 報告が行われる場合がある
   - 報告は後続処理をブロックしない（非同期）

6. **複数承認者**
   - 承認ノードに複数ユーザーが存在する場合あり
   - いずれか一人が承認すれば次のステップへ進行

#### 主要機能
- 承認待ちタスク一覧表示
- 申請内容の詳細確認
- 承認/差戻/却下処理
- 承認履歴の確認
- 進捗状況の確認

### C. ユーザー情報管理

既存のOracleDBからユーザー情報を参照。

#### 参照先テーブル
- **ユーザー情報**: `COMDB.nam_user_admin.e_imdb2_users`
- **承認者情報**: `COMDB.nam_user_admin.e_approver`

#### ユーザー・所属の特性

1. **所属の種類**
   - 本務所属: メインの所属
   - 兼務所属: 兼務している所属

2. **申請所属の選択**
   - 兼務所属がある場合、申請者は申請所属を選択する必要がある
   - 例外: 法務コンプライアンス部（shozoku='2310000'）は兼務所属からの申請不可

3. **承認者の選択**
   - 同一所属に複数の承認者が存在する場合がある
   - 申請者は承認者を選択する必要がある

### D. リソース管理（既存設定の同期）

既存システムの設定情報をOracleDBに定期的に同期。

#### 目的
- 申請時の既存リソース検索・参照
- 重複チェックの基礎データ
- 承認後の自動設定時の差分判定

#### 同期方式
- **日次バッチ処理**: 毎日深夜に外部システム（Google Workspace API等）から最新データを取得しリソーステーブルを更新
- **リアルタイム更新**: 承認後の自動設定実行時に即座にリソーステーブルを更新

#### リソーステーブルの例
- `T_RESOURCE_GMAIL_GROUP`: Gmailグループ
- `T_RESOURCE_GMAIL_ALIAS`: Gmailエイリアス
- `T_RESOURCE_GOOGLE_DRIVE`: Google Driveフォルダ
- `T_RESOURCE_AD_GROUP`: Active Directoryグループ

詳細は[application_action_types.md](application_action_types.md)を参照。

## 3. データフロー

### 新規作成申請のフロー
```
[申請種類選択]
    ↓
[申請区分: 新規作成]
    ↓
[申請者入力]
    ↓
[重複チェック(リソーステーブル参照)]
    ↓
[バリデーション(DBルール参照)]
    ↓
[申請データ保存(NAM_TASK)]
    ↓
[ワークフロー開始]
    ↓
[承認ノード1] → [承認ノード2] → ... → [承認ノードN]
    ↓
[自動設定処理] → [リソーステーブル更新]
    ↓
[報告処理(非同期、申請種類による)]
```

### 修正申請のフロー
```
[申請種類選択]
    ↓
[申請区分: 修正]
    ↓
[既存リソース検索(リソーステーブル参照)]
    ↓
[リソース選択]
    ↓
[既存値自動入力]
    ↓
[申請者が変更]
    ↓
[差分確認]
    ↓
[重複チェック・バリデーション]
    ↓
[申請データ保存(変更前・変更後)]
    ↓
[ワークフロー開始]
    ↓
[承認プロセス]
    ↓
[自動設定処理(差分のみ)] → [リソーステーブル更新]
```

### 削除申請のフロー
```
[申請種類選択]
    ↓
[申請区分: 削除]
    ↓
[既存リソース検索]
    ↓
[リソース選択]
    ↓
[削除対象確認]
    ↓
[削除理由入力]
    ↓
[申請データ保存]
    ↓
[ワークフロー開始]
    ↓
[承認プロセス]
    ↓
[自動削除処理] → [リソーステーブル更新]
```

### リソーステーブル同期フロー
```
[日次バッチ起動(深夜)]
    ↓
[外部システムAPI呼び出し]
    ↓
[データ取得]
    ↓
[リソーステーブル更新(INSERT/UPDATE/DELETE)]
    ↓
[同期ログ記録]
    ↓
[完了通知]
```

## 4. 画面構成（想定）

### 申請者向け画面
1. **ホーム/ダッシュボード**
   - 自分の申請一覧（下書き/申請中/承認済み/却下）
   - 申請種類メニュー

2. **新規申請作成**
   - 申請種類選択
   - 申請区分選択（新規/修正/削除）
   - 入力フォーム（申請区分により動的に変化）
   - 既存リソース検索・選択（修正/削除時）
   - 確認画面
   - 申請提出

3. **申請一覧/検索**
   - ステータス別フィルタ
   - 申請種類別フィルタ
   - 期間検索
   - キーワード検索

4. **申請詳細/編集**
   - 申請内容の詳細表示
   - 下書きの編集
   - 申請の取り下げ

5. **申請履歴**
   - 過去の申請内容
   - 承認履歴の確認

### 承認者向け画面
1. **承認待ちタスク一覧**
   - 自分が承認者として割り当てられているタスク
   - 申請種類・緊急度・申請日でソート
   - 一括承認機能（オプション）

2. **タスク詳細/承認**
   - 申請内容の詳細表示
   - 差分表示（修正の場合）
   - 既存リソース情報の参照
   - 承認/差戻/却下ボタン
   - コメント入力

3. **承認済みタスク一覧**
   - 自分が承認したタスク
   - フィルタ・検索機能

4. **承認履歴**
   - 承認の履歴
   - 統計情報

### 管理者向け画面
1. **ワークフロー設定**
   - ワークフロー定義の作成・編集
   - ノード定義の設定
   - 承認者の割り当て

2. **申請種類マスタ管理**
   - 申請種類の作成・編集・削除
   - フィールド定義の設定
   - リソーステーブルとのマッピング
   - SQLクエリの設定（検索/詳細/重複チェック）

3. **バリデーションルール管理**
   - ルールの作成・編集
   - 正規表現のテスト

4. **プルダウン選択肢管理**
   - 選択肢グループの管理
   - 静的選択肢の編集
   - 動的SQLの設定

5. **リソース同期管理**
   - リソーステーブル一覧
   - 同期ログの参照
   - 手動同期の実行

6. **システム監視**
   - 申請・承認の統計情報
   - エラーログ
   - パフォーマンスモニタリング
